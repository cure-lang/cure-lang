# VS Code Extension for Cure

Official Visual Studio Code extension for the [Cure programming language](https://github.com/cure-lang/cure-lang).

Provides language support, LSP diagnostics, MCP AI integration, and REPL support for Cure **0.34+**.

---

## Features

- **Syntax Highlighting**: Full highlighting for Cure code, including actors, FSMs, macros, decorators, string interpolation, and doc comments, the same as in Zed and Neovim.
- **Language Server Protocol (LSP)**: Automatic connection to `cure-lsp` over stdio:
  - Real-time compile diagnostics
  - Signature help & hover with `##` docs
  - Code completion
  - Auto-formatting on save
- **Native proof goals**: Explorer's **Cure Goals** tree displays targets and
  named hypotheses at the primary cursor, including residual states from refused
  proofs. Run **Cure: Show Proof Goals** (`cure.showGoals`) to reveal it.
- **Model Context Protocol (MCP)**: Deep MCP stdio integration:
  - **Cure MCP: View Stdlib Documentation** (`cure.mcp.getDocs`) — View rich documentation for `Std.List`, `Std.Math`, `Std.Otp`, etc.
  - **Cure MCP: View Syntax Help Topic** (`cure.mcp.getHelp`) — View topic guides (`functions`, `types`, `fsm`, `records`).
  - **Cure MCP: Type-Check Current Document** (`cure.mcp.typeCheck`) — Perform fast dependent type check via MCP.
  - **Cure MCP: View MetaAST Summary** (`cure.mcp.parse`) — Preview full AST structure.
- **Interactive REPL**: Launch `cure repl` in a VS Code integrated terminal (`Cure: Open Interactive REPL`).
- **Snippets**: Handy code snippets for modules, functions, sum types, records, actors, and FSMs.

---

## Commands

| Command | Title | Description |
|---|---|---|
| `cure.showGoals` | Cure: Show Proof Goals | Reveals the native Cure Goals tree and refreshes cursor state |
| `cure.restartLsp` | Cure: Restart LSP Server | Restarts the background `cure-lsp` server |
| `cure.openRepl` | Cure: Open Interactive REPL | Launches `cure repl` in an integrated terminal |
| `cure.mcp.getDocs` | Cure MCP: View Stdlib Documentation | Opens webview preview of stdlib module docs |
| `cure.mcp.getHelp` | Cure MCP: View Syntax Help Topic | Opens webview preview of syntax help topics |
| `cure.mcp.typeCheck` | Cure MCP: Type-Check Current Document | Type-checks active document via MCP |
| `cure.mcp.parse` | Cure MCP: View MetaAST Summary | Shows AST summary via MCP |

## Installation

Requires VS Code 1.82 or newer, matching `vscode-languageclient` 9.

The extension is not on the Marketplace yet. Build it from a checkout of the
Cure repository and install the `.vsix`:

```bash
cd vscode-cure
npm ci
npx @vscode/vsce package
code --install-extension vscode-cure-0.34.0.vsix
```

## Configuration Settings

- `cure.lsp.path`: Path to `cure-lsp` (default: `cure-lsp`).
- `cure.mcp.path`: Path to the `cure` executable, used for `cure mcp` and the REPL (default: `cure`).
- `cure.mcp.enabled`: Enable/disable MCP background client (default: `true`).
- `cure.trace.server`: Traces communication between VS Code and LSP server (`off`, `messages`, `verbose`).

With the default values, the extension looks for `cure-lsp` and `cure` on
`PATH`, then at the root of each workspace folder (a checkout of the Cure
repository has both there). Any other value is used as given; `~` and
`${workspaceFolder}` are expanded. For example, to use a checkout from any
project:

```json
{
  "cure.lsp.path": "~/cure-lang/cure-lsp",
  "cure.mcp.path": "~/cure-lang/cure"
}
```

## Building and testing

```bash
mix deps.get
mix cure.escript
cd vscode-cure
npm ci
npm run compile
node scripts/build-grammar.js --check
npm run test:unit
npm run test:host
```

`syntaxes/cure.tmLanguage.json` is generated by `scripts/build-grammar.js`
(run by `npm run compile`, or alone with `npm run build-grammar`). Edit the
script, not the JSON. `node scripts/build-grammar.js --check` fails when the
JSON is out of date.

Run the commands from a Cure repository checkout; `mix cure.escript` builds the
current server and bundled stdlib rather than relying on a possibly stale root
binary. The official `@vscode/test-electron` development runner downloads VS Code
into ignored `.vscode-test/` and launches the actual extension against that
server. `CURE_TEST_LSP` optionally selects another current server executable;
`VSCODE_TEST_VERSION` selects the test runtime (default 1.95.3).

The host needs an available graphical display. On headless Linux, provision
Xvfb and VS Code runtime libraries, then use `xvfb-run -a npm run test:host`.
`.github/workflows/extension.yml` provisions them and runs compilation, grammar,
Node unit and real-host tests without an unconditional skip.

## Goal-view behavior

The tree uses native theme-aware controls and plain-text tooltips, not
source-derived HTML. Loading, error, unavailable and no-state are distinct.
An empty cursor state is **not** a proof-completion claim: the cursor may be
outside an observed proof or the document may contain errors elsewhere.

Active-editor, primary-selection, text changes and provider saves refresh the view; non-Cure
editors and document closure clear stale goals. Debounced requests keep one
request per live server generation plus the newest desired query. Cancellation
and URI/document-version/position/epoch/generation checks reject late answers.
Startup is awaited and concurrent restarts are serialized. The client relies
on LanguageClient 9's normal document-change flush, not duplicate manual sync.

The host suite checks manifest activation and native view visibility, real
cursor/edit states, E110 residuals, non-goal and malformed source, two files,
multibyte positions and concurrent restarts. Node unit mocks are separate
scheduler/rendering controls, not a substitute for that host gate.

Imported template and computed tactics use the same parsing path as normal
checking/compilation. The active consumer may be unsaved; source providers are
read from their saved files. Saving a provider invalidates dependent analysis
even when the active consumer's version has not changed. Unsaved sibling
provider overlays are not merged, and analysis never overwrites the consumer.
The real host suite exercises these cases in addition to the lifecycle tests.
