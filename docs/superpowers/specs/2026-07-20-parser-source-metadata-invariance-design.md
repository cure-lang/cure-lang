# Parser-Owned Source Metadata and Semantic Invariance

**Status:** implementation specification; required before broad span propagation

**Date:** 2026-07-20

**Parent specifications:**

- `2026-07-20-structured-compiler-diagnostics-design.md`

## 1. Decision

Cure will keep exact authored source information on surface MetaAST throughout
parsing, macro expansion, and elaboration. Semantic consumers must be invariant
under the addition, removal, or replacement of that diagnostic metadata.

Cure will not strip all source information before elaboration. Doing so would
discard the spans needed to explain failures at the checking site. Cure will
also not use an external node-to-span side table: surface nodes are copied,
captured, substituted, and generated by macros, so tuple identity and traversal
position are not stable source identities.

The implementation therefore has three coordinated parts:

1. one typed source-information value stored under one reserved MetaAST key;
2. one recursive semantic projection used by equality, hashing, caches, and
   semantic comparisons;
3. parser-owned construction of exact ranges from lexer token spans.

Broad source propagation must not resume until the semantic-invariance gate in
section 10 is green.

## 2. Triggering failure and root cause

The current parser produces MetaAST nodes shaped as
`{tag, keyword_metadata, children}`. The keyword list contains both semantic
attributes, such as `binder: "x"`, and diagnostic attributes, such as `span:`.

A trial change derived wrapper spans from metadata children. It transformed a
valid dependent-pair type from:

```elixir
{:sigma_type, [binder: "x"], [domain, body]}
```

into the semantically equivalent form:

```elixir
{:sigma_type, [span: span, construct_span: span, binder: "x"], [domain, body]}
```

`Cure.Elab.Declarations.idx_to_core/5` currently accepts only the exact metadata
list `[binder: bname]`. The located form misses that clause and reaches
`{:unsupported_index_expr, ast}`. During the trial this rejected the standard
library across many modules.

This is not a defect in the span value. It proves that semantic behavior still
depends on the incidental contents and ordering of metadata keyword lists.

Three related weaknesses exist at the baseline:

- exact keyword-list patterns occur in semantic consumers, including the
  `sigma_type` and `pi_type` lowering clauses;
- `Cure.Compiler.SourceSpans.strip_diagnostic_meta/1` drops keys from a node's
  own metadata but does not recursively project AST subterms stored in retained
  metadata values;
- formatter, quoting, macro reflection, validation, and tests maintain separate
  lists of source keys, so a newly added role span can silently affect one
  consumer while another ignores it.

A preliminary repository search finds 116 literal keyword-list MetaAST
constructions or matches in compiler, elaboration, and Core-facing code. Not all
are unsafe patterns; the inventory must classify them rather than replacing
them mechanically.

## 3. Required invariants

### 3.1 Semantic invariance

For any conformant surface AST `ast` and any valid source decoration `d`:

```text
verdict(ast) = verdict(decorate(ast, d))
core(ast) = core(decorate(ast, d))
erase(ast) = erase(decorate(ast, d))
emit(ast) = emit(decorate(ast, d))
```

Equality here excludes diagnostic payloads attached to returned errors. An
error may gain a more precise source context, but it must retain the same stable
category and accept/reject verdict.

Source metadata must not influence:

- name resolution, visibility, overload selection, or arity;
- type formation, conversion, normalization, unification, or proof search;
- coverage, totality, positivity, relevance, or erasure;
- macro matching, hygiene, expansion cache identity, or generated names;
- formatting choices other than source-preserving trivia already governed by
  the formatter specification;
- Core terms, certificates, exported interfaces, BEAM forms, or artifacts.

### 3.2 Diagnostic availability

Semantic invariance does not make source metadata disposable. At every surface
checking site, the implementation may read source information and copy the
relevant spans and provenance into a domain error. Once surface syntax is
lowered to Core, Core remains span-free.

Independently supplied Core therefore remains honestly locationless. A Core
failure receives surface blame only when a surface elaboration boundary can
prove the association.

### 3.3 Recursive metadata semantics

Per `Cure.MetaAST.Conformance`, metadata values may themselves contain genuine
MetaAST subterms: parameter types, return types, guards, constraints, patterns,
and clauses are examples. Semantic projection and source traversal must recurse
through those values. Treating the metadata list as an opaque bag is incorrect.

## 4. Source metadata model

Add `Cure.MetaAST.SourceInfo` and store it under the reserved metadata key
`:source_info`.

```text
SourceInfo
  whole          optional exact span for the complete authored construct
  name           optional declaration/reference name span
  callee         optional call target span
  operator       optional operator token span
  operands       ordered operand spans
  arguments      ordered argument spans
  annotation     optional annotation span
  body           optional body span
  pattern        optional pattern span
  guard          optional guard span
  branches       ordered branch spans
  fields         ordered or name-keyed record field spans
  opener         optional opening token span
  closer         optional closing token span
  provenance     ordered provenance frames
```

All fields use `Cure.Diagnostic.Span` or the existing structured provenance
types. Missing information is `nil` or an empty collection; it is never a
line-zero or file-start placeholder.

The initial implementation may retain `:span`, `:construct_span`, `:name_span`,
`:callee_span`, `:line`, and `:col` as read-only compatibility inputs. New parser
code writes only `:source_info`. Compatibility accessors read both shapes until
all consumers migrate. The parser must not dual-write both representations.

`whole` replaces the ambiguous distinction between `:span` and
`:construct_span`. Focused ranges are named roles, not alternate meanings of a
generic span.

## 5. Central metadata contract

Add `Cure.MetaAST.Metadata` as the only owner of source-metadata classification.
It exposes at least:

```elixir
source_info(meta) :: SourceInfo.t() | nil
put_source_info(meta, SourceInfo.t()) :: keyword()
drop_source_info(meta) :: keyword()
strip_diagnostics(ast) :: ast
semantic_equal?(left, right) :: boolean()
semantic_key(ast) :: term()
```

`strip_diagnostics/1` recursively:

1. recognizes canonical MetaAST nodes;
2. removes `:source_info` and every supported legacy source/provenance key;
3. recursively projects every retained metadata value;
4. recursively projects children, lists, tuples, and plain maps;
5. treats structs and opaque payloads atomically unless their owning contract
   explicitly says they contain MetaAST.

`semantic_key/1` returns the same recursive projection and is the required
input to AST-derived hashes and caches. It must not convert strings to atoms or
otherwise change semantic values.

`Cure.Compiler.SourceSpans.strip_diagnostic_meta/1` becomes a temporary delegate
to this module and is deleted with the post-parse attachment bridge.

Independent copies of diagnostic-key lists are forbidden after migration.

## 6. Rules for semantic consumers

Semantic code may bind a metadata variable and read named semantic fields:

```elixir
defp idx_to_core({:sigma_type, meta, [domain, body]}, ...) do
  binder = Keyword.fetch!(meta, :binder)
  ...
end
```

It may not require the complete keyword list to equal a literal pattern:

```elixir
# forbidden in semantic code
{:sigma_type, [binder: binder], [domain, body]}
```

The same rule applies to `case`, `with`, anonymous-function heads, and test
helpers that claim semantic equality.

Semantic metadata fields remain explicit and typed by their owning node.
Ignoring source information does not permit catch-all interpretation of unknown
semantic keys. Node validation may reject an unknown semantic field after
`Metadata.drop_source_info/1` has removed diagnostic fields.

The audit covers:

- `Cure.Elab.Program`, `Declarations`, `Elaborator`, macro expansion, coverage,
  totality, positivity, relevance, erasure, and emission;
- compiler printer, formatter, macro syntax/reflection, macro validation,
  lifting, incremental compilation, and build manifests;
- every AST equality, deduplication, ordering, hashing, memoization, and cache
  key;
- tests and Antigen assays used as semantic oracles.

Add a quoted-code lint under `Cure.MetaAST` that rejects exact literal metadata
lists in pattern position within semantic directories. Parser construction and
tests of malformed raw shapes may use literal metadata lists. The lint reports
file, line, node tag, and pattern.

## 7. Parser-owned range construction

After semantic invariance is established, replace post-parse inference with
ranges constructed in each parser production.

The parser receives lexer tokens whose spans are already exact. Introduce small
range helpers that operate only on spans:

```text
mark(token)                    start at this authored token
through(mark, closing_token)   inclusive construct expressed as half-open span
between(first, last)           merge two same-source spans
zero_at(token_or_eof)          honest insertion position
```

Parser APIs that consume a required delimiter must make the consumed token
available to the production. A new `expect_token/2` may return `{token, state}`;
`expect/2` may remain as a compatibility wrapper where the token is irrelevant.
The parser must not recover a closing delimiter by scanning the completed AST
or guessing its textual width.

Each production owns its range roles:

- declarations: keyword through body/signature end, plus name, annotation, and
  body;
- parameters: variadic/implicit opener through default/type end, plus binder,
  annotation, and default;
- calls: callee through closer, callee token, and one range per argument;
- operators: whole expression, operator token, and operand ranges;
- patterns and match arms: pattern, optional guard, arrow, body, and whole arm;
- conditions and branches: condition and each authored branch;
- records/updates: opener through closer and each field name/value;
- type applications and containers: name/opener through exact closer;
- macro sections: invocation, captured authored regions, template/definition,
  and generated declaration provenance.

Synthetic indent, dedent, newline, and EOF locations remain lexer-owned. A
synthetic token uses an honest zero-width boundary or consumed source range as
specified by the lexer; it never borrows an unrelated token's width.

`Cure.Compiler.SourceSpans.attach/2` remains only as a migration bridge for a
listed set of legacy node families. The allowlist shrinks with every parser
slice. Completion requires deleting inference by token spelling, position
lookup, and delimiter reconstruction.

## 8. Transformations and provenance

Surface transformations follow these rules:

- a copied authored node retains its `SourceInfo` unchanged;
- a rewritten node composed solely from authored children retains role spans
  only when the role still denotes the same authored syntax;
- a generated node does not claim a generated buffer is authored source;
- generated syntax records invocation, definition/template, generated
  declaration, and parent provenance;
- capture, substitution, and hygiene never use source information as semantic
  identity;
- a diagnostic crossing a generated boundary chooses the smallest editable
  authored span and retains generated details only in machine provenance.

Macro reflection must serialize source information through a dedicated source
representation or deliberately omit it according to the macro API contract. It
must not expose the internal keyword layout as user macro data.

## 9. Implementation sequence

### Phase A — establish the metadata contract

1. Add `SourceInfo` and `Metadata` with recursive projection tests.
2. Include all current location and provenance keys in the legacy projection.
3. Replace formatter, quote, macro-syntax, and test-local stripping helpers with
   the central module.
4. Add a decorator used only by tests that inserts distinct sentinel source
   information at every canonical node, including nodes stored in metadata.

### Phase B — make semantic consumers invariant

1. Add the exact-metadata-pattern lint and inventory every violation.
2. Migrate lowering first, including `sigma_type`, `refinement_type`, and
   `pi_type`.
3. Migrate declaration checks, elaboration, macro machinery, static analyses,
   erasure, emission, formatting, hashing, and caches.
4. At each subsystem boundary compare undecorated, decorated, and stripped
   inputs.
5. Keep source context available to domain errors while ensuring returned Core
   and artifacts contain no surface source metadata.

### Phase C — parser-owned ranges by grammar family

Migrate declarations and annotations first, then parameters/calls/operators,
patterns/guards/branches, records/containers, and macro sections. Every slice
adds exact-range tests and removes that family from the inference allowlist.

### Phase D — delete the bridge

Delete `SourceSpans.attach/2`, token-name lookup, delimiter reconstruction, and
all direct legacy source keys. Retain `Metadata.strip_diagnostics/1` as a public
internal contract for equality, testing, hashing, and tooling.

## 10. Verification gates

Broad parser span propagation is permitted only after all Phase A/B gates pass:

1. The targeted dependent-Sigma fixture elaborates identically with no source
   metadata, parser source metadata, and sentinel source metadata.
2. The same three-way comparison passes for representative Pi, refinement,
   union, record, pattern, guard, macro, and dependent-index programs.
3. The frozen verdict corpus has identical accept/reject status and stable
   category in all three modes.
4. Normalized Core, erasure results, exported interfaces, emitted Erlang forms,
   and BEAM output are byte- or structurally identical where determinism is
   promised.
5. Macro expansion and hygiene results are semantically equal, and expansion
   cache keys are identical.
6. The metadata-pattern lint reports zero violations in semantic directories.
7. Repository search finds no independent diagnostic-key lists outside
   `Cure.MetaAST.Metadata` and explicit compatibility tests.
8. A Core-term walk proves no `Span`, `SourceInfo`, source path, or provenance
   frame entered trusted Core.
9. Standard library, examples, focused elaborator/kernel/macro suites, complete
   Antigen, and full ExUnit pass with sentinel decoration enabled.

Each parser grammar-family slice then requires:

- exact UTF-8 byte and line/column ranges;
- whole and focused role ranges;
- plain, ANSI, JSON, and LSP agreement for a diagnostic using the range;
- capture/copy provenance where the construct can cross a macro boundary;
- the full semantic-invariance gate for affected consumers.

## 11. Non-goals

- Moving source spans into Core terms.
- Using source ranges as AST identity or cache keys.
- Fabricating locations for independently supplied Core or generated-only
  syntax.
- General parser recovery or parser self-hosting; those remain 0.35 work.
- Preserving internal keyword-list order as a compatibility contract.

## 12. Completion condition

This work is complete when every parser-owned surface range may be added,
removed, or replaced without changing any semantic result; every reachable
diagnostic can still recover its honest authored context; and the post-parse
span inference bridge has been deleted.
