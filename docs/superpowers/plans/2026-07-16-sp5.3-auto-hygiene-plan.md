## 1. The gate (from `2026-07-12-macro-facility-program.md` / REMAINING-WORK §5.3)

> "auto-hygiene renames template binders with no annotation; `<capture>` still
> binds into caller scope on demand; full suite green."

Concretely: in a Tier-2 `becomes` template, an identifier in an **ordinary
lexical binding position** that the template introduces (a `let`/assignment LHS,
an expression-position lambda parameter, a match-arm pattern variable, a
comprehension binder) must be gensym'd automatically — **without** `<fresh …>` —
together with every reference the template makes to that binder, so a template
binder can never capture use-site material and vice versa. `<capture Name>` is
the on-demand opt-out.

- **`let … in` (expression form)** → `{:block, meta, [{:assignment, [let: true],
  [LHS, value]}, body]}` (`parse_let/1`, `parser.ex:3177-3235`). The LHS is a
  general `parse_expr(_, 6)` result (the parser's own comment at `:3195` notes "a

  DOES parse and bind** (SERIOUS 2 correction):

  "x"}]}`, binding the nested `x`. Only the **paren/brace tuple** LHS forms

  LHS (the assignment's FIRST child) only** — the RHS `value` (second child) is a
  reference/hole scoped outside and must NOT be collected. Scope is the `body`
  sibling.
- **block-form `let` (no `in`)** → `{:assignment, …}` as a child of an enclosing
  `{:block, meta, [assignment, sibling₁, …]}`, binder scoping the **following
  siblings**. **NOTE (v7):** this 3+-child block is **not authorable in a `becomes`
  template** — a template is one `parse_expr` (`parser.ex:6165`), no multi-statement
  block. It is nonetheless AST-**identical** to expr-form `let..in` (an
  `{:assignment}` child scoping its following sibling), so ONE uniform block frame
  (§5 Task 3) covers both — no separate block-form rule needed. A degenerate bare
  `becomes let x = e` (no `in`, nothing after) parses to a lone `{:assignment}` with
  no following sibling to scope (a no-op for the frame).
- **match arm** → `{:pattern_match, meta, [scrutinee, arm₁, …]}` where
  `arm = {:match_arm, [pattern: p], [body]}` (pattern in **meta**,
  `parser.ex:3594`). Every `{:variable, _, name}` **leaf** of `p` (e.g. the `x` in

  binder scoping `body`. **Guarded arm** → `{:match_arm, [pattern: p, guard: g],

  rename frame must span the guard too (MINOR 1). With-rematch arms stash

## 3. Design fork (prose; RECOMMEND lower-risk Option B — review confirmed sound)

**Option A — full set-of-scopes (Flatt / Racket).** Uncopyable scope marks on
every identifier; hygiene falls out of scope-set resolution. The spec-named
ideal, and the model needed for hygiene that survives **serialization across
module boundaries** (SP5.2 cross-module macro import). **Risk: HIGH** — changes
the identifier representation across the parser and every consumer; large
rewrite; broad test churn.

**Option B — template-scoped binding-position auto-freshening (RECOMMENDED).**
Keep the string-gensym substrate; auto-discover ordinary binder names from
binding positions and replace the flat `apply_freshening` with a **scope-aware
walk** (rename frames pushed at each binding form; rename a binder + only the
references it lexically binds; honor shadowing; leave free refs — holes /
caller names — untouched), reusing `mint_gensym`'s collision-avoidance +
hole-exclusion. `<capture Name>` opts a binder out. Same observable gate,
lower risk.

**Soundness of the fork — CONFIRMED by Stage-3 review (`a23355a3`).** The
reviewer tried and **could not** construct a single-module program where Option
B diverges from set-of-scopes given a correctly-implemented walk: `fresh_counter`
is a single **globally-monotonic** counter threaded through parser state
(`parser.ex:1290-1299`), so two mints — across nested expansion, sibling
invocations, or an inner expansion flowing into an outer hole — **cannot**
collide by construction (not by luck); and `collect_used_names` (gap-(b))
already defends caller spoofing within an invocation. The two *exploitable* holes
A was invoked for are already closed. A's only strictly-greater power
(serializable cross-module scope identity) belongs to **SP5.2**. **Decision:
implement B now; record A as the deferred upgrade, revisited iff SP5.2 needs
serializable scope identity.** B's scope-aware walk is exactly where A would
later slot in — no rework wasted.

## 4. SCOPE BOUNDARY (the FATAL finding, resolved) — what auto-hygiene does and does NOT touch

Auto-hygiene applies to a binder **iff** (i) it sits in the **ordinary
expression grammar** (proper AST tuples/keyword-lists), AND (ii) its **scope body
is real AST at freshen time**. This is precisely the set the tuple/list walk can
reach and rename soundly. The discriminator is **tuple-vs-map**, not
"expression-vs-signature": a single-clause fn-def's params live in a meta
**keyword-list** with a real-AST body and ARE renamable; only genuinely
**map-shaped** structures are unreachable and stay out.

**IN scope** (this slice):
- `let`/assignment binders — ONE uniform block frame (v7): inside a `{:block, _,
  children}`, each `{:assignment}` child binds over the FOLLOWING children. This
  covers expr-form `let..in` (`{:block, [assignment, body]}`, 2 children — the sole
  template-authorable form) and, identically, any block-form `{:block, [assignment,
  sibling…]}`. Binders = **`{:variable}` leaves of the LHS (the assignment's FIRST
  child) only**, so constructor-pattern `let Some(x) = p in x` binds `x` while the
  RHS `p` is left as an outer reference/hole (SERIOUS 2);
- match-arm pattern binders — **every `{:variable}` leaf** of the arm pattern,
  scoping both the arm `body` **and** the `guard:` in the arm's meta (MINOR 1);
- with-rematch `:parent_patterns`;
- comprehension/generator binders;
- **expression-position anonymous-lambda params** (`{:lambda, [params: [{:param,
  _, s}]], [body]}`) **and single-clause named-fn-def params** (`{:function_def,
  meta, [body]}` with `params:` in meta) — both are meta keyword-lists of
  `{:param, _, string}`; the `{:param, _, string}` string-child gets the dedicated
  rename case. **For the fn-def the param-scope is `[body]` PLUS the `guards:` /
  `return_type:` / `constraints:` meta terms and each param's `type:`/`default:`**
  (SERIOUS 1 — those meta terms all reference the params; a frame missing any would
  leave a guarded/dependent/`where`-clause reference free and let use-site material
  capture it; `effects:` is atom-collapsed and safe). **The frame MUST match
  strictly on the single-child `{:function_def, meta, [body]}` shape** (MINOR 1,
  pass 5): a **multi-clause** fn-def is `{:function_def, meta, []}` with EMPTY
  children and a walkable `params:` signature list in meta — matching on the tag
  alone would wrongly rename those multi-clause signature params, so the
  `[body]`-vs-`[]` children discriminator is what keeps the OUT-set multi-clause
  case a no-op. Closes `syntax withf <e> becomes fn f(x:Int) = e`, the guarded
  `syntax chk <e> becomes fn f(x:Int) when x>0 = e`, and its `where Foo(x)` variant.

**OUT of scope — DEFERRED, documented, and POSITIVELY TESTED as a no-op**: the
**map-shaped** family-signature binders only — the `becomes lift module`
`:callbacks` maps and multi-clause `:clauses` maps and their `{:param, _, name}`
entries. **Why they are excluded, not merely unhandled:**
1. They live in raw Elixir **maps**, which the freshening recursion never walks —
   `apply_freshening_value` returns any non-tuple, non-list value untouched
   (`parser.ex:1416-1422`) — so today they are untouched, and this slice **must
   keep them untouched**. **This map-shielding is the entire no-op guarantee**
   (MINOR 2): it holds regardless of what the callback map *contains* (its `body:`
   is in fact real AST from `parse_expr_or_block`, `parser.ex:5901-5908`), because
   the walk never descends into the map to reach it. The family expander still
   binds callback signature params to that body by **verbatim name-match** against
   `callback_context.parameter_names` (`parser.ex:5914`), so renaming a signature
   param would desynchronize it from every `%[:reply, :ok, state]` / `%[:noreply,
   state]` clause across `Std.Actor/Fsm/Supervisor/App` (`lib/std/actor.cure:77-148`
   et al.) — which is exactly why the map must stay unwalked. (Specific to the
   lift-family path; the plain single-clause `function_def` above is proper tuples,
   not a map — hence its move IN.)
3. `<capture>` cannot even be *written* on such a map param: `parse_typed_params`
   (`parser.ex:4572-4616`) reads a raw identifier token with no `parse_expr` hook
   for a `<capture …>` prefix. (The IN-set lambda/fn-def params reach the walk as
   proper `{:param, _, string}` tuples and need no such marker to be renamed.)

**Consequence for the design:** the walk **must NOT add map-walking**. Keeping
the recursion tuple/list-only is what makes the map-shaped family-signature
binders a guaranteed no-op while the tuple-shaped single-clause params ARE reached.
Hygiene for the map-shaped family-signature params is a **separate follow-on
concern** (tie to family/OTP hygiene, plausibly folded with SP5.2 or its own
slice) — named here as a known limitation, out of SP5.3's DONE bar.

### Task 3 — scope-aware freshening walk (UNIFIED with `<fresh>`)
Replace the flat `apply_freshening/4` with a scoped walk carrying a stack of
rename frames. At each binding form, mint gensyms (via existing `mint_gensym/3`)
for its non-`<capture>` binders, push a frame over the correct scope, rewrite
binder + the references it binds, pop on exit; free refs fall through (holes
handled as today). **Frame shapes (ground-truthed, §2):**
- **uniform block frame (`let`)** (v7 — subsumes expr-form AND block-form) — walk a
  `{:block, _, children}` left-to-right; each `{:assignment}` child mints gensyms
  for its LHS-leaf binders (RHS excluded, SERIOUS 2) and pushes a frame over the
  FOLLOWING children only. This yields both `let..in` (2 children: assignment binds
  the `body` sibling — the sole template-authorable form) and any block-form
  (assignment binds later siblings) with no special-casing; a later `let x`
  re-mints, shadowing an earlier one over the remaining siblings (its LHS is NOT
  renamed to the earlier gensym). A lone `{:assignment}` (bare `becomes let x = e`)
  has no following sibling — a no-op.
- **match arm** (`{:match_arm, [pattern: p (+ guard: g)], [body]}`) — frame spans
  **both the `body` AND the `guard:` term in meta**; binders = every `{:variable}`
  leaf of `p`.
- **expression-position lambda** (`{:lambda, [params: […]], [body]}`) — frame spans
  `[body]`; binders = `{:param, _, string}` string-children of `:params`.
- **single-clause named fn-def** — **match STRICTLY on the single-child
  `{:function_def, meta, [body]}` shape** (MINOR 1 — a multi-clause fn-def is
  `{:function_def, meta, []}` with EMPTY children and a walkable `params:` in meta;
  matching the tag alone would wrongly rename its signature params, so gate on the
  `[body]`-vs-`[]` children discriminator). Frame spans `[body]` **PLUS the
  `guards:`, `return_type:`, AND `constraints:` (the `where` clause) terms in meta
  and each param's own `type:`/`default:`** (SERIOUS 1 — all three meta terms
  reference the params; a frame missing any leaves a guarded/dependent/`where`
  reference free to be captured; `effects:` is atom-collapsed and needs no
  coverage). Binders = `{:param, _, string}` string-children of `:params`, renamed
  via a **dedicated `:params`-slot string-child case** (the only place a bare string
  in meta is treated as a binder occurrence — do NOT rename bare strings in any
  other meta slot).
- **comprehension / generator** (MINOR 2, pass 5 — REVERSE-scope frame, do NOT use
  the generic "following body" model) — `{:comprehension, meta, [body |
  generators_and_filters]}` (`parser.ex:2829`) with generators
  `{:generator, [], [pattern, collection]}` (`parser.ex:2875`). The binder pattern
  is the generator's **FIRST child** (not meta), and it scopes the comprehension
  `body`, which is an **EARLIER sibling** in the comprehension's child list, PLUS
  the following generators/filters. Binders = every `{:variable}` leaf of each
  generator `pattern` (the `collection` second-child is a reference/hole, excluded);
  the frame must cover the earlier-sibling `body` and the later generators, NOT a
  nested body. (Confirm surface syntax in Task 0 before relying on the exact child
  order.)
- **with-rematch arm** — `{:with_rematch_arm, meta, [body]}` (**distinct tag** from
  the plain `{:match_arm, …}`; ground-truthed at `parser.ex:3734-3744` in Task 0)
  where meta carries BOTH `parent_patterns:` (a LIST of patterns) and `pattern:`
  (the with-pattern); binders = every `{:variable}` leaf of BOTH pattern sources,
  frame spans `[body]`. (Rematch-arm guards are deferred in the parser —
  `parser.ex:3730-3732` — so no `guard:` slot to cover here, unlike the plain arm.)
**`<fresh Name>` markers fold INTO this walk** as a frame spanning "rest of
template" (matching today's template-global behavior) — ONE unified pass, explicit
precedence, so a template mixing `<fresh x>` with an auto-discovered `let x` has a
defined result (Task 5 locks this with a test). **Maps are still not walked** (§4)
— that is the invariant keeping the OUT set a no-op.

### Task 4 — `<capture Name>` marker
Parse `<capture Name>` symmetric to `<fresh Name>` (`parser.ex:2041`) →
`{:capture_name, meta, name}`, lowering in the walk to a plain caller-scope
`{:variable}` the walk leaves untouched. **Reachability limitation (MINOR, pass 4):**
the marker is only recognized in the `parse_expr` `:lt` window (`parser.ex:2041`),
so `<capture>` can be written **only on binders that flow through `parse_expr`** —
`let`-LHS leaves and match-arm pattern vars. **Lambda and fn-def params are read as
raw identifier tokens** (`parse_lambda_params` `:4801`; `parse_explicit_param`
`:4591` — the same `parse_typed_params` path that also backs the IN-set single-clause
fn-def at `:4249`, not only the OUT-set), with no `parse_expr` hook, so a marker
cannot be written there: **IN-set lambda/fn-def params are always auto-renamed with
no opt-out.** Documented limitation (capturing a template's own param into caller
scope is rarely wanted); adding a marker hook to `parse_typed_params` is a possible
follow-on, out of this slice. (§4 OUT binders are unreachable by design and need no
marker.)
