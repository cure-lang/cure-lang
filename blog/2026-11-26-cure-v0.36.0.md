Cure `v0.36.0` is the largest release since the dependent pipeline landed in `v0.34.0`, spanning **178 commits** across the type theory kernel, the proof and tactic engine, the Agda soundness development, and every supported editor.

In [v0.35.0](https://cure-lang.org/blog/2026/10-11-cure-v0.35.0), Cure established its first machine-checked soundness proof in Agda alongside a standalone Tree-Sitter grammar and audit-driven kernel hardening. In `v0.36.0`, Cure takes three decisive steps toward interactive proof-assistant ergonomics on the BEAM:

1. **Full Agda-style universe polymorphism (Phase 5, U0–U7)** — removing the fixed three-level `Type 0 : Type 1 : Type 2` ceiling, introducing canonical maximum-plus level algebra, surface universe syntax and use-site inference, polymorphic standard-library families (`Equivalent`, `List`, `Option`, `Sigma`), and verified grade-0 erasure with byte-identical BEAM output.
2. **Interactive proof tooling, extensible tactics & checked solvers (Phases 1–4)** — live goal-state introspection across CLI diagnostics, REPL (`:goals`), LSP (`cure/proofState` + hole-goal inlay hints), and a native VS Code goals tree; template and typed goal-inspecting computed tactic macros; checked `search`, `assumption`, `positivity`, `decide`, and bounded `omega` solvers; explicit `@simp` admission; deterministic `rewrite using h all`; and automatic proof-admission totality.
3. **Mechanised soundness expansion & executable certificate replay** — growing [`proof/`](https://github.com/cure-lang/cure-lang/tree/main/proof) from 18 to **238 Agda modules** with CI axiom-surface guards, mechanised confluence and erasure, native dependent-typing soundness, and an executable Elixir-to-Agda wire format that replays checked certificates end to end.

Alongside these language and metatheory milestones, `v0.36.0` delivers a broad sweep of fixes and quality-of-life improvements across `cure-lsp`, `cure fmt`, Neovim, VS Code, Zed, `highlightjs-cure`, and the web playground, plus a new linear resource pool example ([`examples/cure_pool/`](https://github.com/cure-lang/cure-lang/tree/main/examples/cure_pool)).

## 1. True Universe Polymorphism (Phase 5, U0–U7)

Previously, Cure's Core kernel lived inside a fixed three-level hierarchy (`Type 0 : Type 1 : Type 2` capped by `Universe.ceiling/0`), and surface names like `UniverseLevel`, `TypeN`, `TypeLimit`, and `Type(0)` were parsed as ordinary type variables rather than universe expressions.

`v0.36.0` replaces that fixed ceiling with end-to-end **Agda-style universe polymorphism**:

- **Canonical maximum-plus level algebra (`Cure.Core.UniverseLevel`)**: Every universe level is represented in canonical maximum-plus normal form (`%UniverseLevel{constant, atoms}` with sorted, deduplicated `{atom_term, offset}` entries and constant subsumption). Operations (`zero`, `closed`, `atom`, `succ`, `max`, `equal?/3`, `leq?/3`, `shift/3`, `subst/3`, `free_vars/1`) preserve normal form by construction, and `validate/2` rejects malformed or non-canonical representations.
- **Unbounded cumulativity**: `Universe.ceiling/0` has been removed. Trusted sorting and cumulativity now operate over arbitrary canonical levels, and every Core traversal walker was audited and upgraded to be level-aware and fail-closed.
- **Surface syntax & use-site inference**: `UniverseLevel`, `universe_zero`, `universe_succ`, `universe_max`, `Type(l)`, `TypeN`, `TypeLimit`, and `TypeLimitN` are now first-class surface forms with least-upper-bound (LUB) inductive family sort inference, level unification, and use-site inference.
- **Polymorphic standard library (82 modules)**: `Std.Equivalent`, `Std.List`, `Std.Option`, and `Std.Sigma` are now single universe-polymorphic definitions across the entire 82-module standard library (71 in `lib/std/` + 11 in `lib/std_deps/`).
- **Zero runtime cost (U6)**: Universe-level parameters are strictly grade-0 erased. Any runtime-relevant use of a universe level is rejected during elaboration/erasure, and emitted BEAM bytecode is verified byte-identical to the monomorphic baseline.
- **Adversarial property testing (U7)**: Antigen now includes universe-polymorphic and adversarial generators, canonical maximum-plus shrinking, and §19.6 weak-kernel sensitivity antibodies.

## 2. Interactive Proofs, Extensible Tactics & Checked Solvers

Guided by [`docs/LEAN4_PARITY.md`](https://github.com/cure-lang/cure-lang/blob/main/docs/LEAN4_PARITY.md) alongside a pinned parity corpus (`test/lean4_parity/`), `v0.36.0` closes Phases 1–4 of the interactive proof-engineering roadmap.

### Live Goal-State Introspection Everywhere

Writing proofs without seeing the remaining goal state is working blind. `v0.36.0` wires `Cure.Elab.ProofState` and `Cure.Elab.SourceContext` through every user-facing surface:

- **CLI (`E110`)**: Unfinished proof diagnostics now render the exact remaining target and authored local hypotheses.
- **REPL (`:goals`)**: Displays proof states for the latest definition submission — even when the definition is refused — without installing the failed definition into the session.
- **LSP (`cure/proofState` & hole-goal inlay hints)**: Responds to cursor positions in the negotiated UTF-8/16/32 encoding, enforces document version consistency (`-32801` on stale/closed buffers), and renders expected types at typed holes directly inline.
- **VS Code (`cure.goals` & `cure.showGoals`)**: A native Goals tree view with request coalescing, cancellation, and automated verification against the real VS Code Extension Host in CI.

### Checked Tactics & Extensible Proof Commands

- **Unified tactic engine (`Cure.Elab.Tactic`)**: Justification commands run through a single checked goal API (`ProofGoal.new/5`, `inspect_goal/1`) that preserves original-goal identity and checked proof evidence across sequence, choice, focus, all-goals, and bounded repeat combinators.
- **Application sessions & canonical-frame induction**: `apply` retains immutable pending parent goals with telescope-ordered independent premises, staged dependent premises, and explicit witness obligations for unresolved implicits. Ordinary induction and induction templates execute checked goal commands per branch with hygienic field and induction-hypothesis (`IH`) names.
- **Library-defined tactics**:
  - **Template tactics (`tactic ... becomes ...`)** let libraries define reusable, contextual proof commands inside macro containers.
  - **Typed computed tactics (`Std.Tactic`)** receive captured `Syntax` arguments and a typed `Std.Tactic.Goal` (with `Hypothesis` records and structural target syntax), returning requests from a closed 256-operation vocabulary with fresh invocation handles and explicit `fresh(...)` hygiene markers. Crucially, the trust boundary never shifts: every expanded request is re-checked by the Core kernel against the original obligation.

### Checked Solvers, `@simp`, and `rewrite ... all`

- **`by search`**: Local evidence, checked projections, and tagged lemmas (retaining ambiguity errors rather than guessing silently).
- **`by assumption`**: Strictly local propositional evidence.
- **`by positivity`**: Curated natural-number `IsPositive` fragment (successors, addition, multiplication, sign hypotheses).
- **`by decide` / `by decide using expr`**: Normalises `Decision(P)` exclusively through certified Core and extracts checked `Yes` evidence at the original goal.
- **`by omega`**: Reconstructs checked `Std.Proof.IntOrder` evidence from local hypotheses, reflexivity, transitivity, additive monotonicity, and literal-natural scaling (bounded to 128 local slots, depth 12, 512 steps, scalars ≤ 1024).
- **`@simp` / `@lemma(:simp)`**: Explicit simplification admission guarded by a strict Core-size termination check (`E112` on non-decreasing or binder-containing endpoints), alongside certified recursive computation (`beta`, `iota`, `zeta`, certified `delta`).
- **`rewrite using h all`**: Deterministic left-to-right multi-occurrence rewriting via composed checked equality transports, leaving single-occurrence rewriting as the default.

### Automatic Proof-Admission Totality

To prevent nonterminating recursive definitions from sneaking into logical proofs just because kernel typing accepts a recursive application, hole-free declarations that execute proof syntax or implicit search now require totality certification automatically (`E013` `proof_totality_unproven`). Unlike `@total true`, this requirement cannot be waived with `@total false` — while ordinary partial runtime functions remain completely legal.

## 3. Mechanised Soundness & Executable Certificate Replay (`proof/`)

Between `v0.35.0` and `v0.36.0`, the Agda formalisation grew from 18 modules to **238 modules**, backed by a new CI job (`ci(proof)`) that machine-checks the entire development and guards its exact axiom surface:

- **Confluence & honest classical soundness**: Proved the diamond property and confluence of `_⇝_` via value-free strict parallel reduction `⇉`. Along the way, we discovered that the earlier classical postulate `never-reached→no-value` was **false** for binder-reducing `_⇝_` (since `tm-lam g d Ω` is a canonical value that steps to itself forever). Both the false postulate and the theorem built on it were retired and replaced by the honest, zero-postulate normal-form dichotomy `soundness-nf : Reached ⊎ DivergesNF` (`Proof.SoundnessConfluence`).
- **Mechanised erasure & §8 regressions**: Proved `erase-idem` with zero postulates and added regression suites for `docs/SOUNDNESS.md` §8 (hole firewall on both paths, SCC verifier rejecting forged partitions, erasure-commutation congruence, and the negative `δ`-commutation result).
- **Native dependent-typing soundness**: Built `Core.DependentTyping`, `Proof.DependentSoundness`, and `Proof.DependentSoundnessModel` proving general dependent transport, conversion inversion, recursive native subject reduction with checked literal layouts, and constructive fuel/trace/tree soundness.
- **Executable Elixir-to-Agda certificate replay**: Added `Cure.Core.ProofWire`, `ProofSnapshot`, `ProofSnapshotWire`, `ProofRecipe`, and `ProofContext` to serialise canonical executable snapshots and recipe certificates from Elixir and replay them in Agda — closing the M1 acceptance gate on a genuinely dependent converted argument, and discharging representation and adapter obligations (host-shaped table resolution, failure impossibility for three evaluator raise sites, narrowed `δ`-unfolding policy, and typed `η` preserving head separation).

## 4. Linear Resource Pool Example (`examples/cure_pool/`)

`v0.36.0` ships a complete Cure + Elixir/OTP resource pool example demonstrating what quantitative and dependent types buy in real BEAM infrastructure. Where ordinary runtime pools catch misuse only in production, `examples/cure_pool` rejects three classic pool bugs at compile time (verified by negative compile-fail fixtures) while preserving OTP supervision and crash-reclaim semantics:

- Checking out from an empty pool (`checkout_empty.cure`)
- Returning a lease twice (`double_return.cure`)
- Dropping an active lease without returning it (`dropped_lease.cure`)

## 5. Editor, LSP, Formatter & Compiler Fixes

`v0.36.0` resolves a long list of everyday friction points across the toolchain:

- **Single-source-of-truth editor grammars (`mix cure.editors.sync`)**: Generates keyword lists from `Cure.Compiler.Lexer.keywords/0` and stdlib declaration macros into `tree-sitter-cure`, `vscode-cure`, `neovim-cure`, and `highlightjs-cure`, checked automatically by `mix test`. All editors now highlight `/.../` regexes accurately (replacing bogus `~r/.../` rules), `##`/`###` doc comments (removing nonexistent `#| |#` block comments), `behavior`, and `directly`.
- **`neovim-cure`**: Native Tree-Sitter highlighting on Neovim 0.11+ (`:CureTSBuild`), working installation instructions pointing at `cure-lang/cure-lang`, a single LSP client per project root, and `.cure` icons via `nvim-web-devicons`.
- **`vscode-cure`**: Finds `cure-lsp` and `cure` on `PATH` and across workspace folders, expands `~` and `${workspaceFolder}`, honours `cure.trace.server`, adds extension/file icons, and auto-indents after trailing `=` or `->`.
- **`cure-lsp`**:
  - Hover now displays `##` documentation alongside full signatures (parameter types, return type, and effects), following `use`/`as` aliases and `Cure.toml` source paths, and preserving trailing `?` on predicates.
  - Frames stdio `Content-Length` in **bytes** instead of Unicode characters, eliminating protocol desync on multi-byte UTF-8 files.
  - Semantic tokens now come directly from the lexer (contextual keywords only in keyword position, never inside comments or strings).
  - Fixed inlay hint and code lens line numbers, constructor classification, and removed redundant `# fn ...` hints and unimplemented `Type | Effects` lenses.
- **Lexer & doc comments**: `##` blocks now start on their own line; a `##` block touching the first definition documents that definition rather than the enclosing module (with module docs separated by a blank line, aligned across the stdlib).
- **Formatter (`cure fmt`)**: Indents every line of a multi-line node in the algebra formatter.
- **Diagnostics & CLI hardening**:
  - Unfilled holes reaching canonical emission render as user-facing `E014 UNFILLED HOLE` instead of `E101 CODE GENERATION FAILED`.
  - Unresolved modules report `E091` instead of `E101`.
  - `cure help` is generated from a single `Cure.CLI.Commands` registry; `cure watch --action` validates input at the CLI boundary (`E099`); `Term.from_external/1` decodes `atom_lit` through existing-atoms-only `sym_atom/1`; `cure migrate` exits via `exit({:shutdown, 1})`.
- **Web playground**: Syntax highlighting in `site/` is now powered by `tree-sitter-cure`.
